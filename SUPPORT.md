# Support

## Bugs and reproducible problems

Open a GitHub issue and use the bug-report template. Include the smallest safe reproduction, the affected commit or version, environment details, and relevant logs with secrets removed.

## Feature and documentation requests

Use the appropriate GitHub issue template. Describe the problem or use case before proposing an implementation.

## Security-sensitive reports

Do not post credentials, tokens, private operational data, database dumps, or vulnerability details in a public issue.

Follow [SECURITY.md](SECURITY.md). When GitHub private vulnerability reporting is available for this repository, use it for suspected vulnerabilities.

## Trading and financial advice

This repository is an engineering and research project. Project support does not provide personalized trading or investment advice and does not make profitability guarantees.

## Scope

Maintainer support is best-effort. Reproducible bugs, documentation gaps, tests, security improvements, and narrowly scoped engineering contributions are the most actionable reports.
